# 人设设计框架 v2：从真实交易反推受众愿意相信的人

**这是可检验的设计方法，不是已证实的营销定律。** 2026-10-19旧版过分强调“现有能力与样品”，容易把人设研究缩成作品展示；新版将高势能角色设计、消费群体与产品成交同时纳入。

## 三个可能的起点，最后都要闭环

- 已有付费需求/商品：买家是谁 → 购买动机与顾虑 → 他愿意信任什么角色 → 内容和视觉 → 商品承接。
- 已聚集高价值客群：他们反复为什么付费 → 选择具体商品 → 设计可信卖方角色 → 转化。
- 已观察到有效人设：反查真实SKU/购买链 → 核收入和成本线索 → 再考虑复制。不能从风格好看推测盈利。

## 五层系统

**1 客户与钱。** 角色不面向所有人：客户是在采购礼品、找懂行的供应商、买独特审美产品，还是购买复杂问题的确定性？预算和真实风险是什么？

**2 可交付产品。** 有规格、成本、定价、售后与履约机制的真实产品或待验证原型；不要求本人全部生产，可外部供给，但要能承担真实承诺。

**3 角色原型。** 例如严谨的供应链买手、隐身专业事务所、少量精选的设计主理、懂行的垂直圈层观察者。角色是商业界面对外的稳定定位，不必与用户真实生活身份绑定。

**4 潜在信任信号。** 通过长期一致的视觉、选择性呈现、行业词汇、自己的判断框架、真实样品与有意义的拒绝/边界，使买家主动推断专业度、资源或审美。必须区分“我们想让他觉得什么”与“实际有公开受众这样反馈”。没有资格的事实性声称不能靠包装顶替。

**5 内容到订单。** 以真实场景吸引 → 用差异展示建立判断 → 商品选项/价格 → 公开可见咨询或购买入口 → 真实交付 → 复购/转介绍。观察断点的地方，不画成已成交的漏斗。

## 每个组合至少回答

客户最怕什么？同类普通卖家哪里让他不放心？这个角色的哪种具体内容改变了风险预期？客户买的究竟是商品、选择能力、代办、省心、资源还是身份符号？产品为什么不被上游直接替代？第一批客户通过什么搜索词或内容找到号？

账号运营可有多个独立定位，不要求同一个人设通吃所有商品；一号一类清楚期望，多号需要比较内容供给、维护和业务冲突的成本。

## 最小设计卡

**商品与买家**／**客户真实疑虑**／**卖方角色**／**三种有根据的视觉与话术线索**／**三类具体内容栏目**／**一个明确成交入口**／**完整交付与责任**／**需要实测的信任假说**／**失败时终止条件**。

这张卡不能证明市场、收益或溢价；只有A需求证据和B真实对标支持下，才向用户申请发布/成交试验。
