# 项目说明

本项目回答：如何通过真实能力的呈现、持续内容和清楚的交易设计，使特定客户愿意信任并购买？研究对象是已经设置明确变现路径的人设账号，优先图文、专业作品、无需持续出镜的方式。研究完整交易链，而非只学配色、头像和标题。

用户要求约 20 个真实对标，拆人设、消费心理、引流承接、价格梯度、成交交付和可复制性，形成案例库与可复用框架。必须考虑个人能否通过合理学习与努力进入；重资历、强人脉、成熟团队支持的模式可研究机制，不强推为新人路线。

## 本轮交付

1. 逐案公开来源与证据边界，保留停售、迁移、价格冲突和购买断点。
2. 内容如何降低买方疑虑、商品如何与信任一致的跨案分析。
3. 从需求、角色、证据、商品、承接、交付到复购的设计工具。
4. 可小规模检验的方案，以及给 A 的市场反馈；均标未做交易验证。

没有订单后台或真实购买体验时，不宣称已确认盈利、复购率、转化率、学习结果或买方愿意支付的因果溢价。公开结账与交付承诺构成可观察路径，付款后实际履约另属验证层。

## 模块接口

| 模块 | 负责问题 | B 如何协同 |
|---|---|---|
| [A：商业机会调研](https://github.com/Sisu-z/business-research) | 卖什么、谁付钱、交易与能力门槛 | 接收明确需求和供给边界；回传反复付费的客群线索，不能以 B 的人气替代 A 的需求证据 |
| B：本仓库 | 信任如何形成，交易路径如何设计 | 保存原始案例出处与适用条件 |
| C：商业决策知识库 | 观点、商业思想及实证经验 | 提议可反驳的方法和证据，经过接收再沉淀，避免将推断写成定律 |

参考 C 和个人技能库用于缩小盲区，旧商业故事和个人背景均不作为当前市场结论，也不在公共仓库复制私人资料。

## 承载与版本

GitHub Issues 是唯一任务源；Markdown 是研究正文，JSONL 是可比较的索引。研究分支 PR 供查看和接收。采用 [project-team-playbook 0.3.0](https://github.com/Sisu-z/project-team-playbook/tree/286bdec328cde8d7593a08308ea47d794ef081da)，只采用启动、边界明确的独立研究、复核及交接，不建立固定部门。当前支持在线接手；离线需要同时取得同版本指南及私有证据包，公共仓库本身不含原文档案。
